# tfstylus のテストディレクトリ

- tfstylus の変換処理をテストする
- 開発中（未リリース）のテストでは、事前にビルドし直しておくこと
- 各ディレクトリの `README.md` からコードフェンスを抽出し、`*.tf` ファイルを生成する
- 何度でも繰り返しテストできる
- デフォルトでは、すべての変更をテスト対象とする（行コメントを `//` としておく）
- 行コメント `//` を `#` に変更すると、該当箇所を ignore できる
- task 自体は親ディレクトリから呼べる（`task tf:xx`）し、terraform ディレクトリ以下なら `task mk` のように tf 名前空間はなしで呼べる

## 作業手順

作業の流れ：

1. テストファイルの生成
2. `tfstylus plan` による目視確認
3. テストファイルのコメント修正
4. `tfstylus plan` による ignore の確認
5. テストファイルの削除

### 1. テストファイルの生成

- 各ディレクトリの `README.md` から `*.tf` ファイルを生成する

```sh
# デフォルトは 001
task tf:mk

# 002 以降
task tf:mk NUM=2
```

### 2. tfstylus plan による目視確認

- tfstylus plan を実行して差分を確認する
- 全ディレクトリのテストファイルを作成して同時実行もできる（差分が多すぎて確認しにくい）

```sh
# tfstylus plan --recursive
task tf:sp
```

### 3. テストファイルのコメント修正

- 生成されたテストファイル（`*.tf`）のコメント `//` を `#` に変更すると ignore が有効になり、処理結果を制御するテストができる

### 4. ignore の確認

- 期待値と比較確認する
- ファイルレベル、ブロックレベル、置換等、それぞれのテストで確認する
- apply して実行確認してもよい

```sh
# tfstylus plan --recursive
task tf:sp

# tfstylus apply --recursive
task tf:sa
```

### 5. テストファイルの削除

- 各ディレクトリの `*.tf` ファイル（前述の手順で生成）を削除する

```sh
task tf:rm
```
